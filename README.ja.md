# Sinless for Foundry VTT（非公式）

TRPG **Sinless** を Foundry Virtual Tabletop で遊ぶための、非公式のファンメイド・システムです。
出版社とは無関係で、承認も受けていません。プレイにはルールブックが必要です（ルール本文は含みません）。

## 主な機能

- キャラクター／NPC アクター。6能力値、4つのダイスプール（剛力・技巧・集中・決意）を
  Sinless の端数処理で自動計算。肉体／朦朧コンディション・トラックと負傷ペナルティ、
  エチケット、キスメット・プール、ゾエティック・ポテンシャル。
- 判定ダイアログ：上限（技能＋装備）、ボーナス／ペナルティダイス（ペナルティはまずボーナスを相殺）、
  グループ技能での代用（−2）、未修得（4成功＝1成功）、出目1／1・2の振り直し、
  キスメット・ダイス、衝突中のプール消費。
- チャットカード：成功数、アーグル・バーグル・フーファロウ判定、判定後のキスメット追加ボタン。
- 攻撃ダイアログでの射撃の修正：明るさ、遮蔽、至近距離、伏せた目標、照準（単純アクション 1 回につき精度分、最大 2 回）、
  追加の目標、二丁拳銃（−1、精度なし）、武器の距離修正。
  リコイルはキャラクターに蓄積する（単純アクションの射撃 2 回で 1 個、フルオートで 2 個）。
  許容量は筋力 12／24、アクティブ・エフェクト（`system.combat.recoilBonus`）、武器のリコイル補正で決まる。
  許容量に達すると攻撃は自動的に外れる。「安定させる」ボタン（と戦闘の終了）でトークンを取り除く。
- 技能の専門化：専門分野に当たれば +1、それ以外の用途では −1。専門化の名前が武器・呪文・乗り物の名前に含まれていれば、
  ダイアログで最初からチェックが入る。
- 攻撃カードはターゲット中のトークンを記録する。防御側はダメージダイアログを開き、回避とソークをその場でロールできる。
  ダイアログが計算するアーマーの扱い：
  - 対弾アーマーと貫通の比較（朦朧／肉体）
  - 対衝撃アーマーからアーマー貫通を引く
  - エネルギー兵器によるアーマー損耗
  - 爆発
  その後コンディショントラックに書き込む（朦朧→肉体→超過とあふれる）。
- NPC はクリーチャー・ルールの固定防御ダイス（回避／ソーク／抵抗）を使える。プールは消費しない。
  空欄ならプレイヤーと同じくプールから振る。武器にも同様に固定の攻撃ダイスを設定できる。
- キャラクター作成パネル（新規キャラクターは作成モードで始まる）。主な内容：
  - 優先度（A〜E）の選択
  - 予算をリアルタイムに表示：能力値ポイント（10／15 を境にコストが上がる）、技能ポイント（武術は 2 倍、儀式を含む）、知識（知力×2）、エチケット（魅力×2）、ズズ（装備・雇用アセット・前払いの生活費）
  - ルールチェック：優先度の重複、出自・魔法に必要な優先度、作成時の技能上限 6
  - ゴースト・レーティングとシードマネーのロール
- アクター・アイテムのアクティブ・エフェクト。アイテムの効果は、防具なら装備中、装備品なら携帯中だけ適用される。
  インプラントの効果は常に適用される。主な変更キー：
  - `system.attributes.str.value`
  - `system.pools.brawn.bonus`
  - `system.condition.physical.bonus`
  - `system.armorBonus.ballistic`
  - `system.skills.firearms.rank`
  - `system.initiativeBonus`
  - `system.zoetic.bonus`
  能力値の欄は元の値のまま表示され、編集できる。それ以外で効果が値を設定している欄はロックされる。
- イニシアチブ＝反応＋集中プール全部の成功数。NPC は固定値。戦闘ラウンドごとにプール自動回復。
- ワールド設定：ラン難易度（ベテラン／プロフェッショナル／プライム）、オペレーショナル・ヒート、
  コンディション基本マス数、負傷ペナルティの有無。
- アイテム：武器、防具、装備品、インプラント、呪文／能力、儀式、知識技能、アセット、リソース、サイバーデッキ、ソフトウェア、車両制御リグ（VCR）。
- 魔法（第 9 章）：
  - 呪文は「魔術＋フォーカス」で決意プールから振る。フォースは習得した値まで選べ、ダイアログにドレインの値と致命かどうか（フォースがゾエティック・ポテンシャルを超えると致命）を表示する。
  - 呪文のカードにはダメージ（例：`1+Force`＋純成功数、アーマー無視）が記録される。標的は防御ダイアログから、呪文で指定されたプールで抵抗する。
  - 術者はカードからドレインに抵抗する：「チャネリング＋フェティッシュ」で振り、朦朧ならさらにソークできる。朦朧は最低 1 マス埋まる。
  - 精霊は「召喚術＋フォーカス」で召喚し、精霊のフォース（精霊バッグで減らせる）と比べる。カードに束縛した奉仕の回数を表示する。呼び出しはフォースと同じ値のドレイン。
  - 増幅はゾエティック・ポテンシャルを消費する（アンプは半分）。儀式には固定のドレインを設定できる。
- ドローンと乗り物（第 8 章）。独立したアクター種別として扱う：
  - ボディ、武装重量、移動、ハンドリング、ハードニング、アーマー、慣性、肉体と車体整合性のトラック。ボディはソークのダイス数でもある。
  - キャラクターをシートにドロップするとリガーになる。リガーが機動・オーバードライブ・体当たり・搭載武器の判定を、運転／操縦または砲術で振る。上限にはハンドリングまたは精度を足す。
  - ペナルティ：操作方法（手動 −4、VCR −2、ホットシート 0）、乗り物のダメージ、慣性。
  - ホットシート中のリガー：VCR ダイスを足せる。乗り物の代わりに回避し、乗り物のダメージを朦朧で受ける（VCR のハードニング分は軽減）。
  - 貫通がアーマーを下回る武器は乗り物に効かない。
  - 体当たりのカードは両者へのダメージを計算し、慣性を 0 に戻す。
- デッキング（第 7 章）。グリッドタブで行う：
  - 装備中のデッキの MCP ダイス、スレッド、コア、I/O、ナーヴリグ、凝集トラックを表示。
  - ソフトウェア判定は「技能＋ソフトのレーティング」が上限、「集中＋MCP ダイス」がプール。MCP ダイスを先に消費し、ラウンドごとに回復する。
  - 侵入難度（ワールド設定）とナーヴリグなしのペナルティを自動で付ける。
  - 機器のハック、NAN の力押し／潜入ハック。カードには獲得する影響範囲（40 m 以上の範囲ペナルティ込み）と、上昇するアラート（シャドウ・プロトコルで軽減）を表示する。ボタンで影響範囲（ロールした本人）とワールドのアラート・レベル（GM）に反映する。
- セクター・プレイ用のブランド・アクター：5つの能力値、ブランド特性、時価総額／維持費／貯蓄、
  セクター・ヒートの効果、セクター・アクション判定（ヒート上昇・有能の自動成功）、ターン終了時の繰り入れ、
  ダメージ／影響力トラック付きのリソース、メンバー管理、最適なメンバーによるアセット判定。
- 最初から多言語対応（英語・日本語）。

## 開発

ビルド不要です（Foundry が ES モジュールを直接読み込みます）。

```sh
ln -s "$PWD" "<FoundryData>/Data/systems/sinless"
npm test             # ルールの単体テスト＋i18n チェック
npm run check:i18n   # 言語ファイルのキー・プレースホルダ整合性
npm run lint:syntax  # 全モジュールと JSON の構文チェック
npm run check        # 上の 3 つをまとめて実行
npm run build        # dist/sinless.zip を作成
```

`main` への push と PR では、GitHub Actions がこれらのチェックとビルドを実行します（`.github/workflows/ci.yml`）。

### リリース手順

```sh
npm run bump -- 0.9.0                 # system.json と package.json のバージョンを更新
$EDITOR release-notes/v0.9.0.md       # 1 行目の「## Title / タイトル」がリリース名になる
git commit -am "Release v0.9.0" && git push
git tag v0.9.0 && git push origin v0.9.0
```

タグを push すると `.github/workflows/release.yml` が動き、次を順に行います。
1. チェックを再実行する
2. ビルドする
3. タグと両方のマニフェストのバージョンが一致するか確認する
4. `sinless.zip` と `system.json` を GitHub Release として公開する

公開せずにローカルで確認するには：`npm run build && DRY_RUN=1 node tools/release.mjs v0.9.0`

foundryvtt.com にパッケージが登録されたら、その *Package Release Token* をリポジトリの Secret `FOUNDRY_RELEASE_TOKEN` に入れてください（`gh secret set FOUNDRY_RELEASE_TOKEN`）。リリースのワークフローが Package Release API で各バージョンを一覧に通知します（`tools/foundry-release.mjs`）。Secret が未設定の間は、この段階を飛ばします。

表示文字列は直接書かず、必ず `lang/en.json` と `lang/ja.json` の両方にキーを追加してください。
訳語は暫定です。用語集の確定に合わせて `lang/ja.json` を更新してください。
