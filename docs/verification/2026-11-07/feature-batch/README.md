記録日: 2026-11-07。Foundry 14.365、ワールド sinless-test、system 0.13.3(ワールド再起動後に確認)。

- 実行: `node docs/verification/2026-11-06/current/batch.mjs`
  (`SINLESS_PLAYWRIGHT` の設定は [../../README.md](../../README.md) を参照。出力先は `SINLESS_VERIFY_OUT`)
- 結果: [regression.json](regression.json)、各スクリプトの出力は [batch.log](batch.log)

`original/` の射撃・状態・成長・オペレーション・生活費・チェイス・デジタル戦闘・魔法 2 本を、1 つのブラウザーで順に実行する。

## テスト用データ

これらのスクリプトは、以前の別スクリプト(roll、damage、npcatk、creation、brand、rig)が残した
`SMOKE D Ben` などのアクターを前提にしていた。ワールドの整理でそれらを削除したため、
[../../2026-11-06/current/fixtures.mjs](../../2026-11-06/current/fixtures.mjs) で同じ前提を直接作る。

- `SMOKE D Ben`(PC、VCR 付き)、`SMOKE D Guard`(NPC、SMOKE Pistol と SMOKE Cudgel)
- `SMOKE C Rookie`、`SMOKE Member`、ブランド `SMOKE Black Adder`(Member が所属)
- `SMOKE V Van`(ホットシート、Minigun)と `SMOKE V Roto`(どちらも Ben が操縦)
- `SMOKE Scene`(アクティブ・表示中)に Ben と Guard のトークン

開始前にワールドの Actor・Item・Scene・Combat・チャットと system 設定(intrusion、alert、heat、operation、chase)を記録し、
終了時に、増えた文書の削除と設定の復元を行う。同名のテスト用データが既にあれば何も作らずに止まる。

## 合否判定

上の照合を [../../2026-11-06/current/batch-checks.mjs](../../2026-11-06/current/batch-checks.mjs) に書き起こした。
`batch.mjs` が各スクリプトの出力を取り込み、判定に 1 つでも失敗すれば終了コード 1 になる。`original/` のスクリプトは変更していない。

- 判定するのは、前提データや入力で決まる値(ダイス数、状態、設定値、文書の数)と、値どうしの関係だけ。
  関係の例: ドレイン − チャネリングの成功数 = 受けたダメージ、持続呪文の必要成功数 = ダイアログの表示。
- ダイス目で変わる値は範囲で判定する(隠密判定のアラート上昇 0〜2、HTR 到着 2〜12 ラウンド、縮小は 2 m 単位)。
- カードやダイアログの文章は翻訳されるため、文章からは数値だけを読む。

| スクリプト | 判定数 |
|---|---|
| shoot | 12 |
| cond | 10 |
| adv | 9 |
| op | 10 |
| life | 3 |
| chase | 7 |
| digital | 8 |
| magic | 5 |
| magic9 | 9 |

確認:
- 本日の 3 回の実行の出力では、すべての判定が成功した。合否判定を加えたあとの実機での実行も 73/73 が成功し、実行後のワールドは空だった。
- 当時のログに当てると、前提データの違う cond で 2 件が失敗した(検出できることの確認)。
  - 1 件は肉体トラックの最大値と修正値。当時の Ben は能力値が上がっていた。
  - もう 1 件は失血までのラウンド数で、1 ラウンド経過して 3 → 1 になっていた。
    今日の 3 回の実行ではいずれも 3 → 2 で、1 ラウンドにつき 1 減るルールどおり。
    残留データの多かった当時のワールドでのみ起きたもので、現状では再現しない。
