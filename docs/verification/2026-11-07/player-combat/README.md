# プレイヤー視点と戦闘進行 / Player view and combat flow

記録日: 2026-11-07。Foundry 14.365、ワールド sinless-test、system 0.13.3。

- 実行: `node docs/verification/2026-11-06/current/extra.mjs`
  (`SINLESS_PLAYWRIGHT` の設定は [../../README.md](../../README.md) を参照)
- 結果: [player-combat-results.json](player-combat-results.json)(6 回連続成功のうち最後の 1 回)

一時ユーザー(プレイヤー権限)、その PC、GM の NPC、専用シーンを作り、GM とプレイヤーの 2 つのブラウザーで操作する。
終了時にすべて削除する。

## 結果

6 回連続で全 10 項目成功。製品由来のコンソールエラーなし。実行後のワールドは空。

| 項目 | 内容 |
|---|---|
| プレイヤーの自分のシート | 所有者・GM ではない・編集可能 |
| プレイヤーの技能判定 | チャットカード作成 |
| プレイヤーが GM の NPC を攻撃 | カードに NPC が対象として記録され、プレイヤー側には防御ボタンが出ない |
| GM が攻撃を処理 | GM の防御ボタンからダメージを適用 |
| 所有していないシート | 読み取り専用。持続呪文の適用は「そのアクターの所有者ではありません。」で拒否され、値は不変 |
| イニシアチブ | PC はロール、NPC は固定値 |
| 手番開始の通知 | 過負荷と持続呪文の抵抗を所有者へ囁き |
| 手番の進行 | 消費したプールは回復しない |
| ラウンドの進行 | プールと MCP が回復 |
| 戦闘終了 | リコイルを解除 |

## 以前のタイムアウトと失敗の原因(すべて検証スクリプト側)

- プレイヤーの `game.ready` が 90 秒でタイムアウト: プレイヤーを GM と同じブラウザーコンテキストで開いていた。
  Foundry のセッションは Cookie 単位なので衝突する。プレイヤーを別コンテキストで開くよう修正。
- 攻撃カードの対象が空になることがある: `createEmbeddedDocuments` が返すトークンの順序は入力順と限らず、
  `tokenIds[1]` がプレイヤー自身の PC のトークンになる回があった(自分自身は対象から除外される)。
  トークンをアクター ID で選ぶよう修正。戦闘参加者の登録も同じ前提に依存していた。
- カードのボタン操作後の停止: Playwright がクリック後のナビゲーションを待っていた。画面内で完結するクリックに `noWaitAfter` を指定。
- 権限の確認: v0.13.0 以降の `applySustained` は詠唱時の対象を先に確かめるため、偽のカードに対象を追加。
  日本語の通知文「所有者ではありません」に合わせて判定の正規表現も修正。
- `AudioContext` のエラー: ヘッドレスのブラウザーに音声デバイスがないためのダイス音のエラー。除外対象に追加。
